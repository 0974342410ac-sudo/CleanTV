# Quick settings panel (remote's quick settings key, com.android.newsettings / com.xgimi.misckey code inside it):
# the tile names live in /data/data/com.android.newsettings/databases/misckey_config.db, and newsettings downloads
# the panel config from XGIMI's server on start (MisckeyManager.fetchConfigData -> saveMisckeyConfig), writing the
# Chinese names back. EROFS partitions and the shared system uid rule out overlays and a per-app firewall, so
# tools/xgimi-vi/dohko-quick-panel-vi.ps1 (adb root) puts SQLite triggers in that DB that rename each tile as it is
# written (2026-10-22, checked on the remote). Original DB: /sdcard/misckey_config.db.bak. A newsettings update
# that rebuilds the DB drops the triggers: run the script again.#
# Power-off menu (com.xgimi.shutdown) has no vi strings and showed English: 49 strings translated in
# tools/xgimi-vi/dohko-shutdown-vi.tsv, installed as fabricated overlay com.android.shell:VietHoaTatMay by
# dohko-shutdown-vi.ps1 (2026-10-22; -Remove takes it out).
# The quick panel's date line stays Chinese (owner's choice, 2026-10-22): TopInfoAndFuncCell formats it with the dex
# literal "yyyy年M月dd日" and DateUtil's "星期一..星期日" and calls setText directly, so no overlay or DB can reach it.#
# Fabricated overlays (VietHoa for Settings, VietHoaTatMay for the power menu) are dropped at every boot on this

# "boot_script": true, so the launcher (BootScript.java) runs boot.sh through the TV's own adbd after each boot.
